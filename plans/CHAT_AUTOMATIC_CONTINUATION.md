# Automatic reply continuation and Stop — backend 35

The 768-token generation size is now an internal segment size, not a total answer limit. A length finish automatically requests the next segment and appends it to the same streamed/saved assistant answer. Normal EOS stops naturally; there is no Continue button. Prose segments have paragraph breaks. Fenced code/media JSON is continued without inserted paragraph breaks to avoid corrupting strings. This cannot guarantee perfect semantic continuity from a generative model.

The model still has an 8192-token context. Continuation rolls forward recent output while retaining system instructions and the original current request; older conversation turns can be omitted to fit. Answer tails shrink if needed to fit the continuation window. This does not provide unlimited model memory. Existing per-request generation timeouts still apply. Empty length-limited segments do not spin indefinitely. The old 64,000-character streaming-preview truncation was removed.

Stop appears beside Send during submission and becomes available when an active reply ID is reported. It creates a per-request local cancellation marker. The worker observes it and aborts its current model request, then returns accumulated text as a stopped result. The partial answer is saved with stopped metadata and an explicit display notice. Stale IDs and other conversation targets cannot cancel a newer reply. Stop is separate from unloading the model. Warmup/attachment preprocessing before an active reply is established is not cancelled by this control.

Fixed a late-history refresh race which could replace streaming content: scoped pending replies and load epochs prevent stale loads from overwriting the current view; completed progress polls cannot resurrect an old pending message.

Validation: 88 Python tests passed, including current/stale Stop targeting and partial-history persistence. 29 JavaScript tests passed, including length-boundary continuation, cancellation, stream failures and fenced JSON continuity. A live native Electron Hermes GPU check streamed text, clicked Stop, confirmed saved partial text/stopped metadata, the visible notice, hidden Stop and re-enabled Send, with no renderer errors (maintenance/chat-stop-check.json). Only the disposable test project was removed. Continuation boundary tests use deterministic model streams; a full multi-segment live long-answer benchmark was not run. User conversations and model selections were preserved.

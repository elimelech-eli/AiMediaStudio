# Global media queue — backend 32

Video, image and voice creation, including chat creation cards, submit durable jobs to one global scheduler. Each job owns a stable ID from PND through WIP to FIN. Context, compatible model specification, reference names, continuation parent and supplied settings are captured at submission. Global registry paths are unchanged by workspace selection. Existing immutable uploads and project-owned voice references remain the inputs; pending/running project pins prevent destructive transfers, archive and deletion from removing them.

The Job queue footer button opens an independent workspace view while keeping current work/drafts mounted. It shows running work, all pending jobs in execution order and 30 recent terminal entries. Pending jobs can be dragged or moved with arrow buttons; reorder uses a revision and the complete pending set to reject stale edits. Remove cancels a pending job. Running jobs can be cancelled. Failed/interrupted/cancelled jobs can retry as a new job. Dismiss removes only a terminal queue-history entry, preserving its output. Pause prevents new starts, while an already running job may finish.

Badges: PND queued, WIP running/cancelling, FIN available output, ERR failed, CXL cancelled, INT interrupted. Tree pending-job menus link to the queue. Submission buttons remain usable during another media job; joining existing clips keeps the existing direct-operation admission guard. Ordinary writing chat is not queued; pending media has priority over new chat inference. The queue waits for active chat/warmup/downloads/file operations and checks GPU availability before dispatch. Idle model workers are released before admission. Resource thresholds reduce conflicts but cannot guarantee availability against unrelated software starting later.

`media-workspaces/queue.json` stores state atomically; per-project engine job files provide placeholder/progress/output compatibility. The scheduler uses the existing engines sequentially and preserves segment/chain publication. On restart, pending jobs survive in order, pause survives, and unfinished running jobs become Interrupted for explicit retry. A completed engine result is recovered as completed. A placeholder left by interruption before queue commit is recovered as Interrupted rather than silently stranded. This is restart recovery, not mid-render checkpointing.

# Chat PDFs and drag/drop — backend 33

Drop files onto the chat workspace or choose +. Supported images, videos, PDFs and text/Markdown files merge into the current conversation's attachment draft. Duplicates are ignored; excess counts, unsupported extensions and oversize files fail atomically without losing existing attachments. Removing chips updates the scoped draft correctly. Dropping files does not submit a message or start inference. The prompt remains required.

Limits: four files per message; text 2 MiB, PDF/images 32 MiB, video 256 MiB. Existing video analysis remains four sampled frames, up to 120 seconds, without audio. PDF validation rejects unreadable/password-protected documents and files above 100 pages. Embedded text is extracted page by page; sparse/scanned pages use CPU OCR, up to 12 pages per PDF. Unprocessed pages are explicitly listed. Extracted text is bounded and query-relevant excerpts share the existing 12,000-character attachment budget. Charts, illustrations and layout are not visually interpreted. OCR is fallible; the bundled recognizer was tested with English text, not every language or handwriting.

PDFium and RapidOCR/ONNX Runtime live in isolated `media-runtime/pdf-python`, leaving video/image/voice Python packages unchanged. OCR model weights are bundled locally; references and extraction never leave the desktop. Processing runs in a subprocess with a 180-second timeout and bounded page rendering. Extraction caches belong to the owning project's context folder. Runtime versions and bundled model hashes: media-runtime/pdf-runtime.json; reproducible pins: freevideo-trial/requirements-pdf.txt.

PDFs are Documents assets with the same workspace ownership, transfer/export/import extension support and deletion semantics as other documents. Opening a PDF document in the tree shows extracted text. PDF attachment notes carry page/OCR/excerpt limitations into the conversation and saved assistant analysis limits. Attachments are reference data, not system instructions.

Validation: 86 app-wide Python tests and 25 JavaScript tests passed. Real embedded-text extraction, scanned-page OCR (Invoice total 4200), cache reuse, project lookup, invalid PDFs and page cap were tested. A native isolated Electron check dropped a PDF, image, video and Markdown together, removed/re-added the PDF, rejected an unsupported/fifth attachment, uploaded the scanned PDF through the authenticated chat route and opened its OCR text. All checks passed without renderer errors (maintenance/chat-drop-pdf-check.json). No model inference/GPU generation was started. Disposable project data was purged. Test PDF render is retained in maintenance/pdf-check/rendered.png.

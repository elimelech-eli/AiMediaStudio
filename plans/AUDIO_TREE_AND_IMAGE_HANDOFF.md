# Audio collections and image handoff — backend 37

Audio has exactly two nested collections: Saved voices and Recordings. Saved voices enumerate validated project-owned profile folders, including separate Trash visibility. Clicking a profile opens its reference preview and selects it for a new recording. Its + opens voice design; Recordings + opens narration. Voice-design auditions remain in the working preview and global queue rather than a third tree collection. Existing audition assets/files are retained. Non-design audio, including imports and sound-only/unknown legacy recordings, remains under Recordings to avoid losing access to existing media.

Profile actions support rename, duplicate, trash, restore and protected purge. Partial/missing/hidden profiles are not advertised as saved voices. Purge refuses profiles referenced by recordings or snapshots. Trashing a preferred project voice clears that context default and increments its revision. Queued/active project work blocks profile changes. These operations retain original voice audio; no new voice generation is needed. Profile preview supports WAV/range delivery without resetting its source on each UI poll. Direct profile drag transfers are not added here; existing recording transfers/exports retain their required voice references. Named independent media drafts remain a separate entity-model task.

Image handoff gaps: uploaded reference-only images had no path to video; rendering hid the action when no completed generated job was selected; read-only asset use was blocked by pending project work. The shared helper now handles imported assets, completed image jobs and explicit uploaded reference files. Multiple references have individual buttons instead of choosing one silently. The main Use as video first frame button is in the work header, independent of preview/job visibility. The video form shows the selected name and thumbnail. No render starts until Generate is clicked. Errors appear in the workspace and sidebar. Queue/project ownership and captured video request input names are preserved. Destructive asset mutations remain blocked while the project is busy.
